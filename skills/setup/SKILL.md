---

Допоможи користувачу завершити OAuth-підключення плагіна ЛКЛАУД.

- Основний MCP — `https://dev.nns.in.ua/mcp`. Не запускай локальний Node-сервер чи `npm run configure` для цього підключення.
- Якщо інструменти ЛКЛАУД уже доступні, виклич `get_available_capabilities`. Успішна відповідь підтверджує підключення. Не вимагай профіль, якщо користувач дозволив лише розклад.
- Якщо інструментів немає або клієнт вимагає авторизацію, поясни: відкрий плагін у клієнті та запусти підключення/авторизацію. Не стверджуй, що ти вже відкрив сторінку або завершив вхід.
- На сторінці OAuth укажи адресу власної хмари закладу; після перенаправлення увійди на сайті закладу та підтвердь потрібні дозволи. Повернися до клієнта й повтори перевірку capabilities.
- Адреса хмари запитується сторінкою OAuth компонента `users`. Не обіцяй окремого поля URL в картці маркетплейсу. Підтримуються активні хмари зі спільною головною БД платформи.
- Не проси пароль, access/refresh токени або секрет OAuth-клієнта в чаті. Реєстрацію клієнта виконує хост через DCR; не реєструй тестових клієнтів вручну.
- Якщо відкривається старий локальний сценарій, порадь оновити маркетплейс і перевстановити плагін версії 0.2.0 або новішої. Файли в кеші встановленого плагіна не редагуй.
- За `oauth_disabled`, `oauth_not_configured` або `oauth_schema_required` поясни, що адміністратор має перевірити оновлення `users`, `preference`, налаштування центрального режиму та OAuth платформи. Компонент `cloud` не потрібен.
