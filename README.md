# ЛКЛАУД — плагін персонального API

Окремий пакет плагіна з MCP-сервером для API `users`, реалізованого в цьому проєкті. Працює з одним підключеним обліковим записом хмари закладу та читає лише дозволені йому дані.

Основний manifest запускає локальний **MCP stdio**. Додано також **HTTP MCP із OAuth компонента `users` власної хмари**: `npm run start:http`; цей режим створює окремий контекст доступу для кожного OAuth-запиту. Публікація, встановлення у ваш обліковий запис ChatGPT/Codex та звернення до справжньої хмари автоматично не виконуються. Локальний режим із персональним токеном не можна використовувати як спільну ідентичність усіх користувачів.

## Інструменти

| Інструмент | users API | Призначення |
| --- | --- | --- |
| `get_available_capabilities` | `capabilities` | Перевірити можливості підключеної хмари |
| `get_my_profile` | `users.profile` | Переглянути підключений обліковий запис; scope `profile:read` |
| `get_my_schedule` | `rozklad.my_schedule` | Отримати власний розклад; scope `schedule:read` |

Профіль і розклад включаються в `tools/list`, лише коли відповідні можливості доступні через API. Діагностичний інструмент залишається доступним після відкликання токена, щоб повідомити про потребу переналаштування. Якщо дозвіл на профіль відсутній, розклад усе одно працює за наявності власного дозволу.

Перелік оновлюється під час нового `tools/list`; клієнт із кешем інструментів може потребувати перезапуску MCP-підключення. Кожен фактичний запит повторно перевіряється API хмари. Нові невідомі можливості відображаються з `supported_by_plugin: false` і не перетворюються на довільні інструменти.

## Підготовка хмари

1. Застосувати оновлення `users`, `rozklad` і БД персонального API.
2. Надати потрібним групам права `users.api`, `users.api_access`, для розкладу — `rozklad.api_personal`.
3. Користувач має бути пов'язаний зі своїм активним профілем викладача або студента.
4. Увійти у **власну хмару** та відкрити `/user/api_access`.
5. Створити дозвіл із `schedule:read`; додати `profile:read`, якщо потрібно показувати профіль. Зберегти показаний токен: дозвіл діє 30 днів, його можна відкликати.

Докладний контракт API: [users-personal-api.md](../../docs/users-personal-api.md) у вихідному проєкті.

## Встановлення та обов’язкове налаштування хмари

Потрібні Node.js **22.16+** і npm.

```sh
cd plugins/lklaud
npm ci
npm run configure
```

Під час встановлення користувач обов’язково вказує HTTPS-адресу власної хмари через цей майстер. Майстер попросить адресу, наприклад `https://school.example`, і токен. Вводьте токен тільки у власному терміналі: введення приховане. Майстер перевірить доступ до API й збереже налаштування у `~/.config/lklaud/connection.json` із правами `0600`. Наявний файл замінюється тільки після успішної перевірки нового підключення.

Усі запити надсилаються безпосередньо до компонента `users` указаної хмари. Компонент `cloud` не використовується. Без адреси хмари й токена підключення не запускається.

Токен не записується до плагіна, manifest-файлів або журналів. Не вставляйте його в чат, URL чи команди, які потрапляють в історію термінала. Збережений файл є локальним файлом із секретом, а не зашифрованим сховищем системи.

Додайте **цю папку** як локальний плагін у клієнті, що підтримує формат Agent Plugins. Головні файли — `plugin.json` і `mcp.json`. `${PLUGIN_ROOT}` підставляється хостом під час встановлення. Сам пакет не реєструє marketplace й не змінює налаштування клієнта.

Для клієнта, який приймає лише конфігурацію MCP stdio, вкажіть:

```json
{
  "mcpServers": {
    "lklaud": {
      "command": "node",
      "args": ["/ABSOLUTE/PATH/TO/plugins/lklaud/server/index.mjs"]
    }
  }
}
```

Замініть шлях на фактичний абсолютний шлях. Якщо клієнт не знаходить `node`, у `command` використайте абсолютний шлях до Node.js. Після зміни підключення перезапустіть MCP-сервер у клієнті.

Для перевірки ручного запуску доступне `npm start`. Сервер очікує MCP-повідомлення у stdin, тому відсутність звичайного виводу означає очікування клієнта. MCP-хост має запускати безпосередньо `node server/index.mjs`, як указано в manifest, щоб повідомлення npm не потрапили в протокольний stdout.

### Альтернативна конфігурація

- `LKLAUD_CONFIG_FILE` — абсолютний шлях до іншого JSON-файлу `{"cloudUrl":"https://school.example","token":"…"}` поза пакетом плагіна. Це дозволяє створити окремі MCP-екземпляри для різних підключень без змішування їхніх credentials.
- `LKLAUD_CLOUD_URL` та `LKLAUD_API_TOKEN` — пара змінних середовища, передана процесу через безпечні налаштування хоста. Потрібні обидві: часткове перевизначення не поєднується зі збереженим токеном іншої хмари.

Сервер не завантажує `.env` автоматично. Не пакуйте власний файл підключення разом із плагіном.

## Приклади запитів

- «Покажи мій розклад на сьогодні».
- «Які заняття в мене з 20 по 26 жовтня 2026 року?»
- «До якого облікового запису ЛКЛАУД я підключений?»
- «Які можливості доступні в моїй хмарі?»

Для розкладу дозволені лише `date_from` та `date_to` у форматі `YYYY-MM-DD`. Межі включні, максимум 31 календарний день. Без дат сервер хмари використовує сьогодні та наступні шість днів у власному часовому поясі.

Відповідь містить часовий пояс, дату отримання, заняття та ознаку `truncated`. Порожній список — відсутність занять. Відсутній час залишається `null`. За `truncated=true` звузьте період. Плагін не приймає довільних ID користувача, викладача, групи або URL хмари від моделі.

## Перевірки

```sh
npm run check
npm test
```

Перевіряються manifest-файли, YAML, синтаксис, обов’язкова адреса хмари, прямі маршрути до `users`, відповідність хмари у відповіді OAuth та генерація конфігурації однієї хмари. Відповіді API у тестах змодельовані; доступ до справжнього закладу для тестів не потрібен.

Продуктивний транспорт використовує HTTPS з перевіркою сертифіката, забороняє redirects, обмежує запит 15 секундами й відповідь 2 MiB. Автоматичних повторів немає. Залежності зафіксовано в `package-lock.json`; власний API-ключ OpenAI не потрібен.

## Що робити за помилок

| Ситуація | Дія |
| --- | --- |
| Немає підключення | Запустити `npm run configure` |
| Токен відкликаний, прострочений або змінився пароль | Створити новий дозвіл і повторити налаштування |
| Інструмент розкладу відсутній | Перевірити активність `rozklad`, право `api_personal`, зв'язок із профілем і scope `schedule:read` |
| API повертає HTML або сторінку входу | Перевірити адресу хмари, розгортання API та маршрутизацію Authorization на вебсервері |
| Не застосована схема | Оновити БД компонента `users` |
| Ліміт запитів | Зачекати наступного хвилинного вікна; не запускати паралельні повтори |

## HTTP MCP та OAuth

Користувач указує адресу власної хмари під час налаштування підключення. OAuth endpoints, вхід, згоду та перевірку токенів забезпечує компонент `users` цієї хмари. Запити до компонента `cloud` не виконуються. Кожен HTTP-запит створює окремий контекст доступу; персональний токен локального режиму тут не використовується.

Адміністратор генерує конфігурацію OAuth для `users` однієї хмари:

```sh
node scripts/provision-oauth.mjs \
  --issuer https://school.example \
  --resource https://mcp.example/mcp \
  --redirect-uri https://client.example/callback \
  --output /ABSOLUTE/NEW/PRIVATE/DIRECTORY
```

`--issuer` — адреса тієї самої хмари, яку вказано в підключенні. Генератор створює `single.json` із правами `0600`; файл потрібно підключити до OAuth у `users`. `--redirect-uri` має точно відповідати callback URL клієнта. Файл містить секрети й має зберігатися поза document root та пакетом плагіна.

Запуск після налаштування OAuth у `users`:

```sh
LKLAUD_CLOUD_URL=https://school.example \
LKLAUD_MCP_RESOURCE=https://mcp.example/mcp \
LKLAUD_MCP_PORT=8787 npm run start:http
```

`LKLAUD_CLOUD_URL` є обов’язковою адресою хмари для цього HTTP-підключення. Для різних хмар налаштовуйте окремі HTTP MCP-підключення з власним resource URL. Node-процес слухає loopback; зовнішній HTTPS забезпечує reverse proxy. У віддаленому `mcp.json` потрібно вказати фактичний endpoint та OAuth-клієнт `provided`. Основний manifest запускає локальний stdio.

Офіційні джерела: [формат пакета](https://developers.openai.com/plugins/build/plugins), [MCP-сервер](https://developers.openai.com/plugins/build/mcp-server), [OAuth](https://developers.openai.com/plugins/build/auth). Перед публікацією потрібно розгорнути й перевірити всю інтеграцію на тестовій хмарі.
